# Autonomous-Rover-System — 연구개발 계획

## 1. 프로젝트 정의

**지상 이동 로버를 대상으로, 센서 불확실성과 외란이 있는 환경에서 인식·상태추정·경로계획·피드백 제어를 결합해 자율 임무를 수행하는 시스템을 개발하고 시뮬레이션으로 검증한다.**

이 문서는 연구 목표, 시스템 구조, 단계별 구현 범위와 검증 계획을 기술한다. 완료 조건과 버전은 계획이며, 구현 상태와 실험 결과는 코드·릴리스·실험 보고서에서 별도로 기록한다.

### 연구개발 범위

- 센서 입력에서 환경과 이동체 상태를 추정하고 계획·제어로 연결하는 폐루프 자율 이동 시스템을 구현한다.
- 시뮬레이터의 정답 상태·지도와 센서 측정·추정 결과를 분리한다. 통합 단계의 제어·계획에는 추정·인식 결과를 사용한다.
- 격자 경로 탐색에서 시작해 방향·속도·구동 입력 제한을 갖는 운동 모델과 경로 추종으로 발전시킨다.
- 카메라 또는 깊이 데이터 기반 주행 가능 영역 추정 모델을 개발하고, 인식 오류가 이동 안전성과 임무 수행에 미치는 영향을 분석한다.
- 센서 고장·통신 단절·에너지 제약을 단계적으로 모델링하고 안전 모드와 복구 정책을 검증한다.
- 운용 도구는 임무 시작·중지·상태 확인과 통신 제약 실험에 필요한 범위로 구성한다.

### 단계별 개발 범위

| 단계 | 범위 | 주요 결과물 |
|---|---|---|
| 기초 모델 | M0–M5 | 경로계획·운동 모델·피드백 제어·센서·추정을 연결한 폐루프 시뮬레이션 |
| 인식 및 통합 | M6–M8 | 인식 데이터·기준 모델·비교 실험과 AI 기반 주행 통합 |
| 실행 구조 및 강건성 | M9–M10 | 실행 지연·동시성 분석, 고장·자원·통신 제약 대응 |
| 확장 실험 | M11 | 실제 센서·로봇, 차량 모델 또는 인식·계획 방식 확장 |

AI 인식은 한 과제에 집중해 기준선·개선 실험·실패 분석을 수행한다. 실행 지연은 통합 단계부터 측정하고, 복잡한 동시성 구조는 측정 결과에 따라 도입한다. 대표 장애 시나리오 하나부터 재현한 뒤 실험 범위를 확장한다.

## 2. 연구 목표와 질문

인식·추정·계획·제어의 개별 성능뿐 아니라, 오차와 지연이 폐루프 주행 전체에 미치는 영향을 분석한다.

1. 센서 노이즈·누락·지연이 상태추정과 경로 추종에 어떤 영향을 주는가?
2. 주행 가능 영역 추정의 오류가 경로 선택·충돌률·임무 성공률에 어떻게 전파되는가?
3. 운동·입력 제약을 고려한 경로 추종이 모델 오차와 동적 장애물에 어떻게 대응하는가?
4. 에너지·위험 비용을 고려한 계획이 최단 거리 계획과 어떤 차이를 보이는가?
5. 센서 고장이나 통신 단절에서 임무 지속·정지·복구 정책이 어떤 결과를 만드는가?

각 질문은 기준 방식과 변경 방식의 동일 조건 비교로 검증한다. 성능 개선을 미리 가정하지 않고 개선·악화·실패 결과와 적용 한계를 함께 기록한다.

---

## 3. 프로젝트 시나리오

로버가 장애물과 통행 가능한 영역이 섞인 지상 환경에서 목표 지점으로 이동한다. 초기에는 격자 지도를 사용하고, 이후 카메라 또는 깊이 센서 기반 환경 인식으로 확장한다.

```text
MISSION

시작 위치: (0, 0)
목표: 지정된 목표 지점까지 이동

조건:
- 장애물과 통행 불가능한 영역 회피
- 센서 오차와 불완전한 환경 정보
- 속도·회전·구동 입력 제한
- 이동 중 새로운 장애물 등장
```

운용 도구에서 목표를 지정하면 로버는 센서 기반 상태추정·인식·계획·제어를 반복하며 이동한다. 인식 결과가 불확실하거나 센서가 고장 나면 감속·정지·재계획 등 정의된 정책에 따라 대응한다.

```text
Sensors → Perception / State Estimation → Map / Estimated State
    ↑                                               │
Environment ← Rover Motion ← Control ← Planning ────┘
```

배터리와 통신 단절은 강건성 확장에서 추가한다. 위치·진행 상태·오류 이벤트는 운용 도구에 기록한다.

---

## 4. 환경과 모델링 가정

초기 시뮬레이션은 2D 평면과 차동구동 로버의 단순화한 운동·센서 모델을 사용한다. 모델별 가정과 생략한 현상을 실험 조건에 명시한다.

인식 단계에서는 카메라 또는 깊이 센서 입력과 주행 가능 영역 라벨을 제공하는 환경·데이터를 사용한다. 시뮬레이터의 정답 지도와 센서 입력에서 얻은 인식 지도를 구분한다.

실제 센서·로봇 또는 다른 차량 모델로 확장할 때 모델 차이를 별도로 검증한다. 단순 로버 시뮬레이션의 결과를 실제 도로 주행 성능으로 일반화하지 않는다.

---

## 5. 개발 및 실험 원칙

작은 실행 시스템에서 시작해 모델과 환경 조건을 단계적으로 확장한다.

```text
기준 모델 → 실행·측정 → 오류·한계 분석 → 변경 → 동일 조건 비교
```

초기 제어 실험에서는 정답 상태로 제어기 자체를 확인한다. 이후 센서 오차와 추정기를 도입해 추정 상태 기반 제어로 전환한다. 인식 통합에서는 정답 지도와 인식 지도를 비교하되, 정답 지도는 기준 실험에만 사용한다.

한 번에 변경하는 요소를 구분하고, 모듈별 검증과 폐루프 통합 검증을 함께 수행한다.

## 6. 재현 가능한 마일스톤

각 마일스톤은 실행 방법·입력·완료 조건을 제공한다. 릴리스에는 해당 시점의 구현 범위, 의존성, 실행 명령과 대표 실험 조건을 기록한다.

버전별 실행 파일 또는 스크립트로 재현할 수 있게 하고, 컨테이너는 환경 재현이 필요한 경우에 도입한다. 이 문서의 버전 표기는 릴리스 계획이며 실제 배포 여부는 저장소의 릴리스 기록을 따른다.

## 7. 전체 시스템

```text
                  Mission Manager
                         │
Sensors ──→ State Estimation ──→ Estimated State
   │                              │
   └──→ AI Perception ──→ Map      │
                          │       │
                          ▼       ▼
                    Path / Trajectory Planner
                                 │
                                 ▼
                         Feedback Controller
                                 │
                                 ▼
                         Rover Motion Model
                                 │
                                 ▼
                      Environment → Sensors

Health Monitor / FDIR → Mission・Planning・Control
Minimal Command / Telemetry Tool ↔ Mission Manager
```

FDIR (Fault Detection, Isolation and Recovery)은 이상 감지·원인 분리·복구를 담당한다.

시뮬레이터의 정답은 센서 생성과 평가에 사용한다. 추정·인식 기반 통합 단계에서는 정답 상태·지도를 직접 제어·계획에 주입하지 않는다.

## 11. M2 — Motion & Sensor Foundations

격자 좌표를 직접 바꾸는 이동에서 제어 입력에 따라 움직이는 모델로 발전시킨다.

- 초기 모델: 차동구동 로버의 운동학 모델. 위치 x·y, 방향, 속도, 시간 간격을 표현한다.
- 선속도·각속도 제한을 두고, 이후 가속도 제한·구동 지연·미끄러짐 등 모델 오차를 단계적으로 추가한다. 운동학 모델과 동역학 모델의 범위를 구분한다.
- 세계 좌표계·로버 좌표계를 정의하고 좌표 변환을 검증한다.
- 정답 상태, 센서 측정값, 추정 상태를 별도 데이터로 둔다.

Python으로 모델을 실험하고, 필요한 실행 모듈을 C++로 구현한다. 같은 입력과 시간 간격에서 결과를 비교한다.

완료 조건: 직진·회전·정지 입력에 대한 궤적을 재현하고, 입력 제한과 시간 간격의 영향을 측정한다.

Release: `v0.3 — Rover Motion Model`

## 12. M3 — Feedback Control & Path Tracking

A*가 만든 경로를 운동 모델이 실제로 따라가도록 한다.

- 경로와 시간·속도를 포함하는 궤적의 차이를 구분한다.
- 초기 경로 추종기를 구현하고, 구동계 모델을 도입하면 PID 속도 제어를 연결한다.
- 급회전·포화·목표 도달과 정지 조건을 처리한다.
- 초기에는 정답 상태를 사용해 제어기 자체를 확인한다. M5부터 추정 상태로 전환한다.

측정: 경로 추종 RMSE·최대 오차, 목표 도달 시간, 제어 입력과 제한 위반, 모델 오차에 대한 반응.

완료 조건: 위치를 경로 좌표에 대입하지 않고, 제어 입력으로 목표에 도달한다. 실패 사례와 튜닝 근거를 기록한다.

Release: `v0.4 — Closed-Loop Path Tracking`

## 13. M4 — Noisy Sensors

- 초기에는 encoder·IMU를 단순화한 센서 모델과 가상의 절대 위치 측정을 사용한다.
- 가상 절대 위치 측정은 추정기 검증용 입력이다. 환경에 따라 시각 기반 위치·랜드마크 또는 GNSS 측정 모델 등으로 구체화하고 가정과 오차를 명시한다.
- 노이즈·바이어스·서로 다른 측정 주기·누락·지연을 단계적으로 추가한다.
- 난수 seed와 실험 조건을 기록한다.

완료 조건: 정답과 측정값의 차이를 시각화하고, 각 오차가 위치·방향 측정에 미치는 영향을 설명한다.

Release: `v0.5 — Noisy Sensors`

---

## 14. M5 — State Estimation & Sensor Fusion

- 단순 선형 모델에서 Kalman Filter를 구현·검증한다.
- 방향과 비선형 운동 모델을 결합할 때 EKF 등의 필요성을 판단한다.
- 센서별 시간·좌표계·불확실성을 고려해 측정값을 결합한다.
- 제어기는 추정 상태를 사용한다. 정답 상태는 평가에만 사용한다.

측정: 위치·방향 추정 오차, 센서 누락 후 오차 증가와 복구, 추정 오차가 경로 추종에 미치는 영향.

완료 조건: raw measurement·단순 기준 추정·개선 추정을 동일 조건에서 비교하고, 추정과 제어가 연결된 폐루프를 검증한다.

Release: `v0.6 — Estimated-State Navigation`

## 15. M6 — Perception Data & Baseline

카메라 또는 깊이 데이터 기반 주행 가능 영역 추정을 연구 과제로 설정한다. 데이터와 시뮬레이터를 선정할 때 입력·출력·라벨 체계를 구체화한다.

- 환경의 정답 장애물 목록을 인식 결과로 대신 사용하는 방식에서 센서 입력 기반 인식으로 전환한다.
- 센서 렌더링이 가능한 시뮬레이터 또는 적합한 공개 데이터를 선택한다. 현재 격자 모델에는 영상 생성 기능이 없으므로 센서 렌더링이나 데이터 입력 경로를 별도로 마련한다.
- 라벨·데이터 출처를 기록하고, 장면·주행 구간 단위로 train/validation/test를 분리해 유사 프레임 누수를 줄인다.
- 단순한 비학습 기준 또는 기존 모델을 기준선으로 평가한다.

완료 조건: 재현 가능한 데이터 처리·평가 흐름과 기준선 결과, 실패 사례를 확보한다. 데이터와 패키지의 출처·버전·사용 조건을 기록한다.

Release: `v0.7 — Perception Baseline`

## 16. M7 — AI Perception Development

기준 모델을 학습·평가하고 변경 요소가 인식 및 주행 성능에 미치는 영향을 분석한다.

- Python과 딥러닝 프레임워크로 기준 모델을 학습 또는 미세조정한다.
- 클래스 불균형, 데이터 증강, 모델 또는 손실 함수 변경 중 필요한 개선을 선택하고 비교 실험한다.
- 인식 출력에서 좌표계·센서 기하를 고려해 지도·주행 비용을 만든다.
- 신뢰도가 낮거나 입력이 오래되었을 때 감속·정지 등 대체 동작을 정의한다. 신뢰도 점수만으로 안전을 보장하지 않는다.

측정: IoU 등 과제에 맞는 인식 지표, 위험 영역 누락, 추론 지연, 조건별 실패. 사용한 장치와 입력 크기를 기록한다.

완료 조건: 기준선 대비 개선과 한계를 미사용 시험 데이터에서 평가한다. 실제 센서 데이터가 가능하면 시뮬레이션과의 차이를 추가 평가한다.

Release: `v0.8 — Learned Traversability`

## 17. M8 — Perception–Planning–Control Integration

센서 → 인식·추정 → 지도 → 계획 → 제어 → 센서의 반복을 완성한다.

- 동적 장애물 등장 시 감지·정지·지도 갱신·재계획·재출발을 구현한다.
- 회전·속도 제약을 고려해 실행 가능한 경로·궤적을 만든다.
- 정답 지도 기반 주행과 AI 인식 기반 주행을 같은 시나리오에서 비교한다.

측정: 충돌률, 임무 성공률, 이동 시간, 추종 오차, 재계획 지연. 반복 횟수와 실패 조건을 함께 기록한다.

완료 조건: AI 인식 성능 변화가 주행 결과에 미치는 영향을 동일 조건의 반복 실험으로 분석한다.

Release: `v0.9 — AI-Assisted Autonomous Rover`

## 18. M9 — Timing & Concurrent Execution

- 센서·추정·제어·계획·인식을 필요한 주기로 분리한다.
- timestamp, 오래된 데이터, bounded queue, 동기화와 종료 처리를 설계한다.
- thread·mutex·condition variable을 필요에 맞게 도입한다.
- Python에서 검증한 알고리즘을 필요한 부분부터 C++ 실행 모듈로 옮기거나 추론 런타임으로 연결하고 결과를 비교한다.

측정: 실제 실행 주기, 지연 분포, 기한 초과, CPU·메모리 사용량. 일반 OS에서 측정한 결과와 실행시간 보장 주장을 구분한다.

Release: `v1.0 — Integrated Autonomy Runtime`

## 19. M10 — Robust & Resource-Aware Mission

센서·인식·통신 장애와 자원 제약에서 자율 이동 시스템의 대응을 검증한다.

- 센서 고장, 인식 실패, planner timeout, 저전력에 대한 상태기계와 안전 모드·복구 조건을 구현한다.
- 거리뿐 아니라 에너지·위험을 고려하는 비용을 설계하고 비교한다.
- 최소한의 외부 명령·상태 확인 도구로 통신 지연·손실·단절을 주입한다.
- 연결 없이 계속할 조건과 중지할 조건을 명시한다. 무조건 임무를 계속하는 것을 성공으로 삼지 않는다.

상세 관제 UI·독자 바이너리 프로토콜은 필요할 때 선택적으로 추가한다.

측정: 고장 감지·안전 모드 전환 시간, 복구 결과, 에너지 소비, 제약 위반과 임무 성공률.

모듈 구분이 곧 별도 프로세스·스레드를 의미하지는 않는다. 동작과 데이터 흐름부터 확인한 뒤 필요한 실행 구조를 도입한다.

## 23. 초기 모델의 범위

초기 구현에서는 2D 이동과 단순화한 센서·환경을 사용한다. 고정밀 접촉·마찰 모델, 완전한 SLAM, 복잡한 차량 동역학과 실제 하드웨어 구동은 초기 범위에 포함하지 않는다.

각 요소는 기존 모델의 한계가 연구 질문에 영향을 줄 때 도입한다. 센서 영상이 필요한 인식 단계에서는 해당 입력을 제공할 수 있는 시뮬레이터 또는 데이터셋을 선정한다.

## 29. 실험 재현성과 평가 원칙

- 설정 파일·데이터·코드 버전과 seed를 기록한다.
- 장면·주행 구간 단위의 데이터 분리로 누수를 줄인다. 시험 데이터로 개선안을 반복 선택하지 않는다.
- 기준 방식과 변경 방식의 비교 조건을 일치시키고, 주요 구성 요소의 영향을 분리해 평가한다.
- 개선뿐 아니라 성능 저하와 실패 결과, 일반화 한계를 보고한다.
- 외부 구현·사전학습 모델·데이터·개발 도구의 사용은 적용되는 출처·버전·라이선스와 함께 기록한다.
- 시뮬레이션 결과와 실제 센서·하드웨어 결과를 구분한다. 검증하지 않은 환경의 성능을 주장하지 않는다.

## 32. 단계별 완료 기준

### 기초 폐루프

- 운동 모델·경로계획·센서·상태추정·피드백 제어가 실행 가능한 시스템으로 연결된다.
- 정답 상태와 측정·추정 상태가 분리된다.
- 추정 오차와 경로 추종 오차를 재현 가능한 조건에서 측정한다.

### 인식 기반 자율 주행

- 인식 데이터 처리·학습·평가 흐름과 기준 모델이 재현된다.
- 인식 결과가 지도·계획·제어에 연결되고, 정답 지도 기반 기준 주행과 비교된다.
- 주요 구성 요소의 비교 실험, 인식·주행 지표와 대표 장애 시나리오 결과를 기록한다.
- 실제 센서 데이터가 있으면 시뮬레이션과의 차이를 분석하고, 없으면 검증 범위를 명시한다.

### 실행 구조·강건성 확장

- 실행 주기·지연·자원 사용량을 측정하고 오래된 입력·기한 초과 처리를 검증한다.
- 선정한 고장·통신·에너지 시나리오의 안전 모드·복구와 실패 조건을 기록한다.
- 추가 환경·하드웨어 검증은 해당 모델과 데이터에 대한 별도 결과로 보고한다.

## 33. 개발 우선순위와 변경 기준

M0–M5의 작은 폐루프를 먼저 구성하고 M6–M8의 인식 및 통합 실험을 수행한다. M9–M10은 측정 결과와 실패 분석에 따라 실행 구조·강건성을 확장한다.

기준선과 평가 조건을 확보한 뒤 기능을 추가한다. 새 기술은 기존 모델의 한계 또는 연구 질문을 해결하는 경우에 도입하며, 범위 변경 시 가정·완료 조건·평가 방법을 함께 갱신한다.

## 34. 최종 개발 방향

Autonomous-Rover-System은 **센서 입력을 해석하고 상태를 추정하며, 계획·제어를 통해 물리적 환경과 상호작용하는 자율 이동 로버 시스템**을 개발한다. 지상 로버의 폐루프 시뮬레이션을 기반으로 인식 오류·외란·고장이 임무 수행에 미치는 영향을 분석하고, 실제 센서·로봇 및 다른 이동체 모델로 실험을 확장한다.
